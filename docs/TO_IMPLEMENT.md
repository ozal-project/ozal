## How to maintain this document

States:

- **Ready** — can be implemented with current decisions and code.
- **In progress** — started; not all done criteria met. Link the branch/PR.
- **Verify** — reported earlier but code changed; reproduce before fixing.
- **Blocked** — needs a decision, account or resource not yet available.
- **Planned** — belongs to a later release; not refined yet.

When starting a task, set it to **In progress**. When done, remove it from the
active tables and add it to [`IMPLEMENTED.md`](IMPLEMENTED.md) with commit,
date and evidence. Never duplicate a task in two places.

ID prefixes: `SEC` security finding · `BUG` defect · `REL` release hygiene ·
`ARCH` architecture · `AUD` durable audit · `EDGE` edge/deployment · `TUN`
tunnels · `ID` identity · `CTX` decision context · `SHD` Shield/WAF · `NTF` notifications · `PKI`
private CA · `ACC` infrastructure access · `TLOG` transparency log · `AI`
AI-assisted decisions · `AGT` AI-agent gateway · `UI` dashboard · `PAGES`
static sites · `LAB` learning lab (not a release commitment).

### Context for decisions (2026-10-22)

Thesis from the owner after an Entrust talk: security tools usually fail for
lack of context about what is happening, and context is what sets a product
like Netskope One apart. Today `auth.Authorize(Principal, AccessPolicy)` sees
identity, groups, method, `auth_time` and `device_bound`; it does not see the
device, the network, the resource's sensitivity, the action or history. Entrust's
Biometric Passkey proves *who* more strongly (document + live face matched in
its cloud, mobile SDK only, binding kept by the backend, not cryptographic);
that is a different axis, tracked as `ID-009`.

Design constraints: the context is a typed value built per request, with
every field carrying its **source** and **freshness** (observed by Switchboard,
asserted by a connector, or absent); a missing signal is "unknown", never a
guess. Rules stay explicit and explainable (`policy explain` and the audit event
name the signals used); no opaque score. Aligned with the workspace rule that an
inference is never shown as an observed fact.
