First tagged build of Switchboard: an identity-aware application gateway for
developers and small self-hosted deployments, in one binary and one config
file. **Alpha: not production-ready.** Interfaces, config keys and the state
database may change before 0.1.0.

These notes follow the release contract (`REL-008`): each promise names its
evidence, and what is not promised is listed as such.

## Promise

What this build does, with automated tests behind each line:

- **Host-based reverse proxy** with per-upstream health checks, server
  timeouts on every listener and graceful shutdown.
- **Automatic HTTPS** through ACME (TLS-ALPN-01, and DNS-01 through
  Cloudflare's API), with certificate storage and renewal.
- **Login per route** through an external OIDC provider, and authorization
  by verified email, email domain or group claims. Verified identity headers
  reach the upstream; forged copies from the client are stripped.
  Switchboard is not an identity provider.
- **Configuration you can check before running it:** strict validation
  (`switchboard validate`), secrets as `env:`/`file:` references, routing
  rebuilt as atomic immutable snapshots on reload.
- **Loopback-only control plane** and a local console: route changes that
  persist and install together, reload, status and an activity view.
- **Static sites** (`pages`): immutable deployments with history and
  rollback, `_redirects` and `_headers` validated on upload, a SPA fallback.
- **Optional SQLite state** (`-db`, `switchboard migrate up`): sessions that
  survive a restart, connectors and deployments.

## Evidence

- `scripts/verify.sh` (format, vet, race tests, a short fuzz pass,
  `staticcheck`, `govulncheck`, console build) green on Linux, macOS and
  Windows in CI, on `main` and on a pull request.
- Static sites and the DNS-01 wildcard certificate run on the author's
  own VPS edge; a production deploy and rollback were observed
  through Cloudflare on 2026-10-20. One operator, one host: this is
  dogfooding, not field evidence.
- The archives are built by GoReleaser with `-trimpath` and a commit-based
  timestamp; two builds of the same commit produced identical binaries.
  Each archive has a SHA-256 entry in `checksums.txt` and an SPDX SBOM.

## Not in this release

- **Experimental, off by default and not promised:** the owned outbound
  tunnel and named connectors (`TUN-001`/`TUN-002`: visitor identity through
  a connector is not yet a contract), rate limiting (`SHD-001`, not measured
  under load) and Telegram alerts (`NTF-001`).
- No built-in login (passwords, email codes or passkeys), no OIDC provider,
  no WAF or bot protection, no DDoS mitigation, no CDN, no high availability.
- No claims of tamper-evident or transparent logs; those are long-range
  design directions in `VISION.md`.
- No signed artifacts or provenance yet (`LAB-010`): verify with
  `checksums.txt` over HTTPS from this release page.

## Install, rollback and recovery

Download the archive for your platform, check it with
`sha256sum -c checksums.txt --ignore-missing`, extract and run
`switchboard validate -config config.json`. `QUICKSTART.md` in the archive
walks through a first route.

There is no earlier release to roll back to. State migrations are
forward-only: copy the `-db` file before running `switchboard migrate up`
with a newer build, and restore that copy to go back. Without `-db`,
sessions live in memory and a restart signs everyone out.

## Known limits and residual risks

- Windows is a build and test target; seven config tests that use POSIX
  path fixtures are skipped there. Production use has only been exercised on
  Linux.
- `govulncheck` lists `GO-2026-5932` in `golang.org/x/crypto` with no fix
  available; Switchboard's code does not call the affected function.
- Single-node design: the state database and deployments live on one host
  and are backed up by the operator, not by Switchboard.
- Built with Go 1.27.3, which includes the fix for `GO-2026-6809`
  (`crypto/x509`); builds from source need that toolchain or newer.
